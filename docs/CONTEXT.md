# Domain glossary

The shared vocabulary for Rails. Use these terms in code, UI copy, and docs. If you introduce a new
domain concept, add it here first.

| Term | Meaning | Not to be confused with |
| --- | --- | --- |
| **Project** | A local directory attached to Rails by absolute path. All sessions belong to exactly one project. Stored in our DB. Removing a project only *detaches* it: transcripts stay on disk, and attaching the same path again brings its sessions back. Removal is refused while the project has open panels. | A git repository. A project _may_ be a git repo, but doesn't have to be. |
| **Provider** | A coding-agent product Rails can read and/or drive: `claude` (Claude Code), `codex` (OpenAI Codex CLI), `pi`. Identified by a `ProviderId`. | The LLM vendor or model. Pi can talk to Anthropic models, but its provider here is still `pi`. |
| **Session** | One agent conversation, identified by `(provider, providerSessionId)`. The provider's on-disk transcript is the source of truth for its history. The UI may call these "chats". | A browser connection or login session. |
| **Session name** | A short name the user gives a session in Rails (ADR 0019), shown instead of the agent's title everywhere in Rails; agents and the Coordinator find the session by it. Rails keeps it; the transcript is untouched. | The agent's own title (its `/rename` or `/name`), or a Sprocket's name. |
| **Transcript** | The provider-owned file on disk that records a session (for example `~/.claude/projects/<enc>/<id>.jsonl`). Rails reads transcripts and never writes them. | Our own DB rows, which are only an index. |
| **Discovery** | Scanning provider transcript stores to find sessions whose `cwd` is inside a project's directory. This is read-only. | Attaching a project, which is always an explicit user action. |
| **Adapter** | The server-side discovery code for one provider (`providers/<id>.ts`: `scan`). It finds sessions and their titles. Running an agent is not an adapter's job; panels run the provider's own CLI. | — |
| **Workspace** | A project's arrangement of panels: split panes with tabs. One per project; the layout is saved on the server so every device opens the same arrangement. | The Rails app as a whole. |
| **Panel** | One terminal tab in a workspace, running a provider's native TUI (`claude`, `codex`, `pi`) or a plain `shell` in the project folder. Its process runs in its own tmux session, so it survives browser disconnects and server restarts, and every connected client sees and types into the same terminal. Closing a panel stops its process, and a panel closes itself when its process exits (`exit`, `/exit`, a crash). | A session. A panel may show a session (agents) or none (shells). |
| **Bridge** | How agents in Rails panels report what they do (ADR 0007): Claude Code hooks, the Rails pi extension, Codex's app-server daemon. Each panel has its own bridge token. | The access token, which panels never get. |
| **Board** | Per project, what each open session is doing (status, what it was asked, files it changed, its last reply), folded from what the bridge received. What a Sprocket reads instead of transcripts. | A transcript. |
| **Needs attention** | A panel whose agent waits for the user (a permission, a question, a form) or whose turn failed. Its session dot and tab marker are red. | Busy (yellow), which is only about output. |
| **Busy** | A panel whose program keeps printing output, as an agent does while it thinks or replies. The sidebar shows its session's dot yellow instead of green. | A panel that is merely open (green). |
| **Sprocket** | One of the user's always-on agents (ADR 0005): a shape (one of 8), a colour, one accessory or none, a name, its direct chat and, while attached, its project's chat (ADR 0021). It replies on a model the user sets up and can be attached to one project (ADR 0006). Sprockets replace the earlier "home agent" idea. | A provider or a panel. |
| **Coordinator** | The Sprocket attached to a project: a project has one, and it's the one Rails wakes for its sessions (ADR 0009, 0016). | An unattached Sprocket, which is only for chatting. |
| **Owner** | A session that owns files or folders of its project (ADR 0016), as the user told the Coordinator. Requests about them go to it; another session changing them wakes the Coordinator. | Git's file ownership; the user. |
| **Watch** | How Rails follows a project's sessions for its Coordinator: code that decides when a wait (a question in a dialog, a turn that ends with one, or a permission, ADR 0026) is worth waking it for. | A Sprocket reading the board when asked. |
| **Overlap** | Two live sessions in a project that both changed a file in the last 30 minutes (ADR 0014): they may be working against each other. Both tabs show it, and it wakes the project's Coordinator. | A git merge conflict. |
| **Finding** | A problem or needed change in another session's files that a session names in its reply without telling that session (ADR 0029): Rails wakes the Coordinator, which drafts that session a message or stays quiet. | An Overlap (both sessions changed the file). |
| **Handoff** | Something a Coordinator passes on when one session finishes, for another (ADR 0015): the user asks for it in the chat, Rails wakes the Coordinator at the first session's turn ends, and it drafts the message, which the user sends. | A message sent right away (a Suggestion). |
| **Direct chat** | A Sprocket's own chat with the user (ADR 0021): every Sprocket has one, and it stays when the Sprocket moves. Events never land in it; an attached Sprocket reads them there with `project_chat` when asked. | The project chat; later, team chats with several Sprockets. |
| **Team** | The user and two to four Sprockets in one chat, a team chat (ADR 0022). Every message **wakes** every member (ADR 0033), or only those it @mentions, or for a tapped option whoever asked; each member writes or stays **quiet**. A member's message wakes the others, at most 4 levels after the user's message. No member leads. Any number of teams, belonging to no project. | A project chat, where Rails' events land. |
| **Project chat** | A project's chat with its Sprocket (ADR 0021): where Rails' events and the Coordinator's suggestions land, and what the workspace's side panel shows. It goes when the Sprocket moves to another project. Either chat can be cleared, which deletes its messages, not the Sprocket's memory. | The direct chat. |
| **Event** | A message from Rails in a Coordinator's project chat: which session waits for the user and what it asked, which sessions overlap, or which session a handoff waited for finished. The Coordinator's reply follows, or a "nothing needed" mark. | A SessionEvent, what the bridge records. |
| **Rule** | One of a Coordinator's standing rules (ADR 0011): a plain sentence from the user on how to answer sessions ("If it asks whether to continue with its plan, say yes."). Each suggestion says which rule it followed. | Its description, which covers everything it does. |
| **Suggestion** | What a Coordinator drafts for a session (ADR 0010), shown under its message: an answer to a question the session asked (it expires when the session moves on; a dialog's answer is picked in the panel, unless Rails can answer that pi dialog, ADR 0027), or a message the user asked it to pass on (a busy session gets it after its current turn). The user sends it, edited or not, or dismisses it. | A message a Sprocket sends on its own (not yet). |
| **Look** | What a Sprocket looks like: its shape (`character` in code), colour and accessory. | |
| **Run** | One bounded turn of a Sprocket's in one chat, kept as a row (ADR 0023): queued when the user writes, a teammate's message wakes it (ADR 0033) or an event wakes a Coordinator, then running, then done, failed, cancelled, or **waiting** for the answer to its question. It may post several messages. | A panel's process. |
| **Wake** | Queuing a team member's run because a message reached it (ADR 0033): the user's, or a teammate's. The member reads the chat and decides whether to write; a member that stays quiet replies `(quiet)` and nothing is posted. | A pass, which teams no longer have (ADR 0023, replaced). |
| **Card** | A table, facts, a list, a checklist, code or a diff a Sprocket shows in a direct or team chat with `show_card` (ADR 0024), drawn by Rails; read-only. | A suggestion card, which is a draft reply for a session. |
| **Question** | A Sprocket asking the user (`ask_user`, ADR 0023), with two to four options to tap or none; its run waits, and the user's next message without an @mention for someone else answers it. | A session's question in a dialog. |
| **Description** | What the user wants from a Sprocket, in a few sentences (at most 500 characters): its standing instructions, like a small AGENTS.md. It follows it in every reply and keeps it across projects. | Its core memory, which the Sprocket writes itself. |
| **Agent tools** | Tools Rails gives the agents in its panels (ADR 0018), as an MCP server behind the panel's token (Codex: as dynamic tools on a thread Rails starts, ADR 0030): `neighbours` (the other sessions in the project), `message` (a draft for another session, which waits in the Coordinator's chat until the user sends it) and `wait_for` (until another session finishes what it's doing). Claude Code and pi get them, and new Codex panels in a folder Codex trusts. | A Capability, which is the Coordinator's. |
| **Capability** | Something a Sprocket can do (read the board, a session's conversation, git, a file; remember), as a server function with a schema. The Sprocket's model reaches capabilities through codemode: it writes a script that calls them (ADR 0008). | A Provider's own tools inside a panel. |
| **Core memory** | A Sprocket's own short note (at most 1,500 characters) about its user, kept with its `remember` tool. Internal: not shown in the UI. It stays with the Sprocket when it moves to another project. | Its project chat, which belongs to one project. |
| **Decision model** | A fast model that answers typed questions (yes/no, one of a few options) instead of writing text: a classifier such as TypeSafe's Jev (ADR 0012). It judges in shadow: Rails logs its answers next to its own decisions. Once picked, it may also wake the Coordinator where it's sure and Rails' rules weren't (ADR 0013); `RAILS_DECISIONS=shadow` keeps it to judging. | A Sprocket's model, which writes its replies. |
| **Recent decisions** | The decision model's judgments, next to what Rails decided in code and where a wake led (Settings → Models, collapsed). Called the shadow log when the model only judges. | A Sprocket's run log. |
| **Model provider** | A service Sprockets run on (OpenAI, Anthropic, OpenRouter, …), set up with an API key or a sign-in in Settings → Providers. | A Provider (Claude Code, Codex, pi). |
| **Resume** | Opening an existing session in a panel with the provider's own command: `claude --resume <id>`, `pi --session <id>`, `codex resume <id>`. Opening a session that already has a panel focuses that panel instead. | — |
| **Client** | A browser tab or device connected to the server over WebSocket. There can be many at once, each attached to panels as its own tmux client. | A user. v1 has exactly one user. |
| **Access token** | A shared secret that gates the whole server. v1 is single-user. "Sign out everywhere" (Settings → Account) replaces it. | — |
| **Profile** | The name and avatar (one of 8) at the foot of the sidebar, set in Settings → Account and shared by every device. The name is the computer Rails runs on until the user changes it. | |
| **Saved prompt** | A name and a text the user keeps in Customize to start agents with; Home's composer fills it in. | A Sprocket's description or rules. |
| **Appearance** | Light, Dark or System (which follows the device), chosen in Settings → General and kept per browser, so each device can differ. Terminals stay dark in all three (ADR 0017). | The Profile, which every device shares. |
| **Settings** | The modal for the app itself (this server, model providers, the account), opened from the account row at the foot of the sidebar. Its search finds single settings by name or synonym. | Customize, which holds what Sprockets use. |
| **Customize** | The page for what Sprockets can use (ADR 0025): connectors and other MCP servers, skills and saved prompts, as cards in tabs. Each Sprocket picks its servers and skills in its settings (Tools). | Settings, which is for the app itself. |
| **MCP server** | A program on the Rails machine or a service on the web whose tools Sprockets can call (ADR 0025), kept in Customize with its secrets on the server. A remote one may need the user to sign in (OAuth); Rails keeps the token. Each tool is **allow** (runs), **ask** (an approval first) or **off**. | The agents' own MCP servers, which Rails doesn't touch. |
| **Connector** | An MCP server Rails knows (Linear, Notion, GitHub, Google Drive, …), added from Customize in one step and set up as its entry says (ADR 0025). Once added it is an ordinary MCP server. Google's sign in with the user's **Google app**, registered once in Google Cloud and shared by all of them. | A custom server, which the user sets up by URL or command. |
| **Action** | A call to one of a Sprocket's MCP ask tools, on a card in a direct or team chat: the Sprocket proposes it by calling the tool, and the user runs or skips it there; once all of a card's actions are settled, the Sprocket goes on (ADR 0031). | A suggestion, which a Coordinator drafts for a session. |
| **Approval** | The older card for an MCP call a Sprocket asked to make with an ask tool: Allow runs it, Deny doesn't; the Sprocket goes on in a new turn either way (ADR 0025). Rails no longer makes them (such calls are actions, ADR 0031); ones already waiting can still be decided. | A suggestion, which is a draft for a session. |
| **Skill** | A SKILL.md folder Rails keeps (written in Customize or copied in) that a Sprocket reads with `read_skill` when it applies (ADR 0025). It can't run a skill's scripts. | An agent's own skills, which can be copied in. |
| **Automation** | A Sprocket, a prompt and a schedule (in a timezone): when it's due, the Sprocket runs the prompt in its direct chat without anyone asking, and the run gets an outcome (Done, Nothing new, Needs you, Failed, Skipped). Writes it asks for wait on a card (ADR 0032). Sessions in panels aren't automated yet. A template is a starting point that fills in a new one. | A suggestion or a handoff, which a Coordinator drafts for the user to send. |
| **Harness** _(future)_ | Rails' own agent loop, as opposed to driving a third-party provider. | — |
